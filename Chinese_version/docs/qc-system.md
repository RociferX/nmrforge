# QC 体系

nmrForge 的质量控制用于度量结果并记录对数据的处理。它覆盖 FID 诊断、采样检查与谱图评估。
发现、建议和已执行修正明确区分；工具栏独立检查只读。QC 分数不证明科学正确性。

## 第一层 —— FID 诊断

在**「生成 FID」步骤的最后**运行(转换/合并出 FID 之后、生成谱图之前;结论与处理方式随该步骤日志输出,并落盘 `process/diagnostics.json`;「生成谱图」只读回复用,不重跑)。检测并报告:

| 发现 | 判定规则 |
| --- | --- |
| 直流偏置 | 逐维度比较时域直流分量与信号水平的比值 |
| 非有限点 | FID 里出现 `NaN` 或 `Inf` |
| 全零迹线 | uniform 采样中样本全为零的迹线(「空白行」) |
| 能量异常偏高的迹线 | 迹线能量高于非零迹线能量中位数的 100 倍；此项本身不证明坏点 |
| 损坏的采样点 | 检出项、已执行的源级删除或 FID 清理，以及未执行的原因 |
| 分段频移 | 用户指定并在转换时应用的组间频移；第 1 段使用 0 Hz。软件不会自动估计或复检该频移 |

有两种行为值得注意:

- 非有限值、uniform 空白迹线与持续异常高能量迹线只报告，不自动删除。修正依据具体规则并留档。
- NUS 源级删除前会验证 `ser` 与采样表布局；通过验证后才备份并改写，必要时调整采样网格。
  布局不一致时不会强行删行。首次 `.bak` 不覆盖；若不希望改写项目副本，请先准备工作副本。
- 早先已删除的坏点会根据审计和备份历史在“生成 FID”报告中说明，不计为本次新检出。
- 分段频移使用用户指定的 `segment_shift_hz`，第 1 段为 0 Hz。只有请求值实际应用后才报告为已应用。
  软件不会自动估计频移或保证复检残差；请检查处理后的谱图并判断校正是否合适。

### 工具栏独立数据质量检查

“工具 → 数据质量检查”支持单个 NMRPipe FID 或切片 FID 文件夹。文件夹入口只检查直接子级 `.fid`，
按自然顺序排序、去重并核对直接维长度，不递归进入其他实验。它只读并显示汇总/建议，不覆盖流水线
诊断、运行记录或审计，也不执行场漂校正。

## 第二层 —— 采样检查

采样判定(`core/experiment/sampling_detector.py`)是导入关卡:

- 先过滤不支持的动力学/伪维布局。只认标准 `nuslist` 或由 `acqus.NUSLIST` 明确指名的文件，不扫描目录猜整数表。
- 结合采集参数、有效网格、补零和采样表坐标判断。`NusAMOUNT=100`、转换脚本 N/T 或残留 `Nus*` 参数本身不能证明普通满采样。
- 合法表满覆盖且按标准网格顺序时可走 uniform；满覆盖但乱序仍需按表归位。明确 NUS 却缺表或位置无法还原时，导入报告缺少采样表，而不是编造坐标。
- 声明网格之后的全零 padding 不算漏采点。分段数据按合并表中的唯一坐标统计覆盖率，不使用单段比例。

## 第三层 —— 谱图质量

对处理后的谱图运行(`core/qc/`)。

| 指标 | 模块 | 看什么 |
| --- | --- | --- |
| 噪声水平 | `core/qc/noise.py` | 稳健噪声与全局中位背景 |
| 信噪比 | `core/qc/snr.py` | 峰高相对同一背景与噪声估计 |
| 相位质量 | `core/qc/phase_quality.py` | 峰窗内的净吸收,感知符号口径 |
| 基线质量 | `core/qc/baseline_quality.py` | 逐存储轴看基线平坦度,报出最差轴 |
| 伪影 | `core/qc/artifact_detection.py` | 条纹/波纹一类结构性伪影 |
| 选峰 | `core/qc/peak_detection.py` | 质量报告所用的峰清单 |
| 综合判定 | `core/qc/spectrum_quality.py` | 把以上各项汇总成一个总判定 |

有两个设计决定值得了解:

- **相位评分感知符号口径。**对于确实存在负峰真峰的实验(例如某些 HNN 类实验),
  负峰不是相位错误。实验模板声明期望的符号行为,而模谱实验完全跳过相位搜索。
- **基线评估是相对的,不是绝对的。**一个让条纹比原来更糟的基线校正候选会被拒绝;
  而一个明显改善了本就带条纹的基线的校正会被接受。当条纹属于数据/采集伪影而非基线偏移时,
  报告会直接说明,而不是给出一个不可能奏效的校正方案。
- **信噪比与相位使用同一套符号口径。**`evaluate(sign_mode=...)`把`mixed`映射到`both`，
  与mixed模板选峰一致，并把相同峰清单交给`snr.compute`；正负峰按声明的符号口径参与评分。
- **单符号实验按构造就是正峰。**`uniform` 映射到 `positive`,
  因为处理链对单符号数据的 ±180 歧义是按正吸收消解的(`core/optimization/phase_consensus`
  只对 `mixed` 跳过该步)。因此一个峰以负峰为主的 uniform 谱是**异常** ——
  要么数据整体反号,要么相位从未消歧 —— 判定会用文字说明这一点(「负峰信号占优」),
  而不是去适应被反号的峰、把它当成一张正常谱。分数也会掉,因为信噪比项找不到信号;
  相位项同样会报。
- **独立工具自己判口径,管道内直接声明口径。**两个入口故意不同。
  凡是知道实验类型的调用方 —— 处理报告、优化路径、
  `optimize_post_parameters(..., sign_mode=...)`、参数优化命令行 —— 传 `uniform` 或
  `mixed`,得到上面那套严格读数。凡是不知道的 —— 「谱图质量」菜单项、对用户自己处理过的
  谱图调用的低层 API —— 传 `auto`:判定自己决定这张谱是单符号正峰、单符号负峰,
  还是双符号混合,依据是 6σ 以上的强度质量(噪声到不了那里),以及选峰步骤在混合符号
  兜底时用的同一条 0.15 少数份额规则。判定会写进说明里(「单符号正峰/负峰」「正负共存」),
  而单符号负峰谱是**整体翻转后**再评分的 —— 于是用户自带的单符号全负峰谱会被如实报告为
  「另一极性的正常谱」,而不是「反号数据」,得分也与它的镜像相同。
- **不可评估的输入只报告,不抛异常。**空数组、含 `NaN`/`Inf` 的谱、
  常数(全零)谱或噪声估计为 0,一律返回 `decision=rollback`、`overall=0` 与具体原因,
  而不是让 numpy 在归约里抛错,也不是给一张零信息谱发一个「警告」分。

## 运行报告

每次运行结束时,日志里有三段式报告:

```text
◆ 最终谱图质量     总判定,S/N / 相位 / 基线 / 伪影的分项分,基线指标,以及实际施加过的检查
◆ 数据质量诊断     发现条目数、其中多少被自动处理,以及细节
◆ 处理参数         解析后的参数集,包括优化器选了什么
```

这份报告是写给「要不要相信这张谱」的那个人的:用带建议的文字下结论,而不是甩一堆数字。

## 结构化审计记录(已实现)

自动修正会写成机器可读的记录,而不只是日志行。`core/audit/qc_audit.py` 在每个处理工作目录下
写一份**只能追加**的 `qc_audit.jsonl`(每条记录都 flush,因此被 kill 的运行也仍能交代它
改过什么),字段就是公开发布任务要求的那些:

```text
issue_detected / location / detection_rule / action_taken / before_state / after_state /
timestamp / software_version    (能取到时另有 git_commit / git_commit_dirty)
```

它强制以下规则:

- **没改就没记录** —— 没有记录本身就是「没动过」的证据;
- 时间戳与版本由日志盖章,调用点不可能漏掉溯源信息;
- `before_state`/`after_state` 带具体数值(例如被修复样本的实部/虚部,或旧的与新的 `NusTD`),
  过长的细节列表会被截断并标记 `truncated`,而不是悄悄裁剪;
- 未能执行的源头删除记为 `reported_only`,永不记成「已删除」。

目前写记录的位置:坏点替换(`workflow/direct_diagnostics.py`)、清洗后的采样网格收缩、
以及源级坏点删除(`backend/nmrpipe_backend.py`)。用 `read_audit(work_dir)` 读回,
确切的覆盖范围见 `tests/test_qc_audit.py`。

## 审计范围

`qc_audit.jsonl` 记录已执行的更正，不是每次运行所有 QC 结果的完整快照。未执行的
建议不会记为已校正；用户仍需检查处理后的谱图。审计字段和当前覆盖范围见本页前文。
