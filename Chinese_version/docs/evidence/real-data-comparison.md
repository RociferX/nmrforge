# 真实数据实测证据(公开数据)

本页**只用一套公开数据**:BMRB timedomain 条目 **53374** 的原始 Bruker 数据 `15n-hsqc` ——
狂犬病毒 P 蛋白 C 端结构域(rabies virus P protein C-terminal domain,CVS-11 株)。原始数据公开可
下载,**任何人都能取同一份数据复算**;期望峰位取自同一条目里**作者沉积的主链酰胺化学位移**
(期望峰表本体不进仓库,只留 sha256)。

## 2. 真值回收:处理结果对得上**已发表的化学位移**

第 1 节的图是定性对照,这一节给数字。口径:

- **匹配**:`d = hypot(Δ1H/tol_H, Δ15N/tol_N) <= 1`,**一对一贪心最近优先**;一个检出峰只能配
  一个期望峰,被抢走的期望峰记「未检出」;只有落在谱实际覆盖的 1H/15N 窗口内的期望峰进分母
  (窗口外的峰本来就检不到,本套数据 107 个期望峰全部落在窗口内)。
- **参照**:沉积化学位移与谱自身参照差一个常数,按「容差逐级收紧的网格扫描」标定**一次**后
  **冻结**(标定只看匹配数,不参与选窗/选参)。
- **偶然背景**:把期望峰表**逐峰独立平移** >=5 个匹配半径(固定 seed、200 次),用同一套匹配算
  「随便摆也能配上」的比例 —— 回收率必须连背景一起读。
- **检出与精修都用产品自己的口径**,不改候选峰、不为凑匹配换峰。

| | 狂犬病毒 P 蛋白 C 端结构域(CVS-11 株) |
| --- | --- |
| 数据来源(公开) | BMRB timedomain 条目 **53374**,数据集 `15n-hsqc` |
| 输入指纹(文件数 / 字节 / sha256) | 38 / 16,930,169 / `534d74cc…cca6cd` |
| 期望峰表(sha256;行数 → 落在谱窗口内) | `ad7006b4…f27d0ec7`(107 → 107) |
| 终谱形状(15N × 1H) | 512 × 1264 |
| 全局参照平移(1H / 15N,ppm,标定后冻结) | −0.067 / −0.088 |
| 检出峰数(12σ) | 308 |
| **期望峰回收率**(12σ,**紧容差** 1H 0.01 / 15N 0.05 ppm) | **90 / 107 = 84.1%** |
| 位置残差中位(1H / 15N,ppm) | 0.0012 / 0.0164 |
| 位置残差 p90(1H / 15N,ppm) | 0.0030 / 0.0343 |
| 未匹配检出峰 / 未检出期望峰 | 218 / 17 |

**结论说清楚:在这套真实 HSQC 上,标定一次全局参照后,紧容差下 84.1% 的沉积峰位被一对一复现**
(放宽容差到 0.02/0.10 ppm 是 93.5%,0.05/0.50 ppm 是 97.2%),位置残差中位在 0.001–0.02 ppm
量级;同口径「随便乱摆」的偶然背景在紧容差下只有 2.0%。

| 容差 1H / 15N(ppm) | 回收率 | 偶然背景(同口径) |
| --- | --- | --- |
| 0.01 / 0.05 | **84.1%**(90 / 107) | 2.0% |
| 0.02 / 0.10 | 93.5%(100 / 107) | 6.7% |
| 0.05 / 0.50 | 97.2%(104 / 107) | 35% |

**阈值口径(必须一起读)**:本节统一用 **12σ** —— 参考流程在这类数据上选定的检出阈值。产品默认的
**35σ 是为强信号液体谱准备的默认值**,它的价值是「在更多情形下都适用」,**不是**衡量这套数据的
标尺,因此本节**不报 35σ 下的回收率、也不用它评价处理结果**;阈值由使用者按样品选(软件不替使用者
决定)。这个 12σ 只用于**窗选择时的「应有峰」峰集**(`workflow/window_optimize.py`),与产品选峰
默认阈值(35σ)是两个独立常量,不互相覆盖。

**未检出的 17 个期望峰,逐个量过**(匹配明细 CSV 的 `nearest_id` / `nearest_distance` 两列就是为此加的
—— 它给每个未检出期望峰**最近的检出峰**及其距离,单位就是容差):

- **11 个**的最近检出峰只差 **1.0–1.5 倍容差**:残差几乎全在 15N(0.045–0.072 ppm),1H 全部 ≤0.005 ppm,
  而且这些邻居多数还是强峰(SNR 155–588)。也就是说峰**在**,位置差一点。
- **3 个**差 2.3–2.5 倍;**3 个**真的远(15N 差 0.27–1.43 ppm)—— 这一批更接近「多谱联合指认的峰在本
  条件不存在」那一类。
- 这 17 个里有 **4 个**的最近检出峰已经配给了相邻的期望峰 —— **一对一规则下一个检出峰只能配一个
  期望峰**,被抢走的那个只能记未检出。
- **紧容差贴在数据点分辨率上**:终谱 15N 轴 512 点跨 104.05–132.00 ppm,**一个数据点 = 0.055 ppm**,
  而紧容差是 0.05 ppm,**比一个点还小**。也就是说「配上」要求 15N 位置差**不到一个数据点**;差一个
  点的峰在图上仍旧压在同一团峰形里(所以会看到黑框落在强峰上),按本口径却已经算未检出。放宽容差到
  0.02/0.10 ppm(≈ 2 个点)回收率就到 93.5%,这一档卡的是门槛,不是「没有峰」。
- **参照不是没标定好**(复核时另做的一遍扫描):把全局参照在标定值附近 ±0.06 ppm 内按 0.01 ppm 扫一遍
  —— 同一套匹配口径下,紧容差的最好成绩是 92/107;本页报的 90/107 就是标定器自己的答案,它的目标是
  「容差内匹配数最多」而不是「残差中位最小」,两者差 2 个峰。

**为什么 100% 既不可能、也不需要:**

- 这条蛋白 115 个残基里,条目沉积了 **107 个主链酰胺**:脯氨酸没有酰胺 NH,本来就不在这张表里。
- 第 2 节回答的是「这批沉积峰里有多少能在自动处理终谱上一对一找回」,**不是**「处理错了几个」。
- **未匹配的 218 个检出峰不是错**:沉积指认只覆盖主链酰胺,检出里还有未指认峰、侧链 NH2、以及阈值
  附近的弱极大值;它们**不叫 false peak**,也**不进任何一个回收率**。
- 口径与脚本:匹配与统计在 `workflow/truth_benchmark.py`,真机执行是
  `scripts/vm_truth_benchmark.py`,出图是 `scripts/vm_truth_figure.py`(对比图与真值图同一脚本);
  复现命令见第 5 节。

## 3. QC 评分(这一套数据)

同一口径 `sign_mode="auto"`(先判「单符号正峰 / 单符号负峰 / 正负共存」再评分);**自动处理终谱与
该数据自带的处理谱都裁到同一个 1H 窗口(6.5–10.5 ppm)再评分**,两行才可比:

| 谱 | 综合分 | 判定 | 信噪比 | 相位 | 基线 | 伪影 |
| --- | --- | --- | --- | --- | --- | --- |
| 自动处理终谱 | 95.7 | ✓ 接受 | 100 | 87.5 | 94.0 | 100 |
| 数据自带处理谱 | 96.0 | ✓ 接受 | 100 | 90.4 | 91.9 | 100 |

两条谱都判「接受」,综合分只差 0.3 分。自动处理的相位分略低,是因为**负峰质量占比偏高**(0.39,
软件在 `reasons` 里明确报出);数据自带处理谱的基线分略低。相位评分看全谱正负质量分布,回收率看
指定峰位上有没有峰,两者不矛盾。**引用 QC 分数请连口径(含 1H 窗口)一起给。**

## 4. 自动处理参数

产物里有两个脚本:转换 `process/fid.com`(`bruk2pipe` + `nusExpand` 按采样表展开,再把数据交给
NMRPipe)与终谱 `process/d_001_process.com`。本节是后者**全文**(与产物逐字一致,只省略行末续行符):

| 维 | 处理链 |
| --- | --- |
| 直接维(1H) | `SP -off 0.3 -end 0.98 -pow 1 -c 0.5` → `ZF -size 4096` → `FT` → `PS -p0 300 -p1 0 -di` → `POLY -ord 2 -auto` → `EXT -x1 10.5ppm -xn 6.5ppm -sw -round 2` |
| 间接维(15N) | `TP` → `SP -off 0.45 -end 0.95 -pow 1 -c 0.5` → `ZF -size 512` → `FT` → `PS -p0 272.5 -p1 0 -di` → `POLY -ord 3 -auto` → `TP` → `pipe2xyz -out d_001.ft2 -x` |

每个参数由哪一步决定(产品自己的处理日志也逐项写了同样的归属):

| 参数 | 终跑值 | 由哪一步决定 |
| --- | --- | --- |
| 窗函数 `SP -off/-end/-pow/-c` | 直接维 0.3 / 0.98,间接维 0.45 / 0.95 | **窗选择**(按参考谱评分择优,`workflow/window_optimize.py`) |
| 零填 `ZF -size` | 4096(1H)/ 512(15N) | 零填候选规则(auto:按 TD 与内存定) |
| 相位 `PS -p0/-p1` | 1H 300 / 15N 272.5(p1 = 0) | 相位优化(直接维先定,间接维再搜一轮) |
| 基线 `POLY -ord N -auto` | 直接维 2、间接维 3 | 基线优化(`workflow/baseline_optimize.py`:逐轴在 mode ∈ {off, auto} × 阶数 ∈ {1,2,3} 里评分择优;关掉时是裸 `POLY -auto`) |
| 1H 显示窗口 `EXT` | 10.5 → 6.5 ppm | 数据自身的 1H 范围(终谱实测 1H 6.497–10.502 ppm) |

**优化前(参考谱脚本 `process/d_001_before_optimize.com`)→ 终跑,只有两处不同**:①直接维窗
`SP -off 0.45 -end 0.95` → `SP -off 0.3 -end 0.98`;②两维基线由裸 `POLY -auto` 变成
`POLY -ord 2 -auto` / `POLY -ord 3 -auto`。间接维窗、零填、相位与 1H 窗口都不变。

窗函数候选池与评分口径见 `workflow/window_optimize.py`(2026-09-22 起按「检出强度 × 并峰因子 ×
线形」评分,检出阈值 12σ,分辨率门限由参考谱最近显著峰间距决定)。

## 6. 能说明什么

- **自动处理谱与数据提供方处理谱一致**(第 1 节左/右列,15N 投影互相关位移 +0.005 ppm),
  **且处理结果对得上外部真值**:这套真实 HSQC 上,标定一次全局参照后,作者沉积化学位移里的期望峰在
  紧容差下有 **84.1% 被一对一配上**(中容差 93.5%),位置残差中位 0.0012 / 0.0164 ppm,而同口径的
  偶然匹配背景只有 **2.0%** —— 判据在软件之外,不是自己跟自己比;输入是公开的 BMRB timedomain
  条目,任何人都能下载同一份数据复算。
- **同一输入给同一输出**:3 次独立重复的主峰差为 0(第 5 节),两条谱 QC 都判「接受」(第 3 节)。
- **这次验证要说明的是处理程序的有效性**,不是为了得出科学结论:拿处理结果去做别的科学问题,属于
  使用者自己的事,与本软件无关。
- 软件本身的边界:处理与留档自洽,不替用户下科学结论。
- **还有一批暂时无法公开的数据(维护者自述)**:除本页这套公开数据外,维护者另用**十几套暂无法
  公开的数据**做过验证,自动处理都达到了与人工处理相当的优化效果。这些运行不在本仓库里,因此这
  一段属维护者自述、无法仅凭快照复算;能复算的是本页第 1–5 节的数字
  (`scripts/vm_truth_benchmark.py` + `scripts/vm_truth_figure.py` + 页内已列出的输入哈希)。
