# 批量处理

批量处理把同样的步骤一次应用到多个数据集。它的目的是让例行工作可重复,并且对自己的边界很诚实:
**批量处理只支持 2D。**

## 它做什么

`workflow/batch.py::run_batch` 接收一组数据条目(通常是某个数据组的全部成员,或某个实验里的
全部数据),对每一个跑流水线步骤。

关键行为:

- **运行前先查组内一致性。** 组内各数据集的参考谱参数会被比对;处理参数与组参考不一致的数据集
  会被报出来,而不是拿不同的设置默默处理掉;
- **已完成的步骤跳过。** 每个步骤记输入指纹;步骤已是 `DONE` 且指纹一致的数据集不会重算,
  所以批量在中断后可以重跑;
- **失败被隔离。** 一个数据集失败不会中止整批:失败记在该数据集上,批继续跑;
- **非 2D 数据集带理由跳过。** 不会用 2D 近似去处理它。这条是内部审计记录里的 `BATCH-012`。

## 怎么用

GUI:`工具` → 数据组 → 批量运行。进度按数据集报在该组作用域的日志里,项目树显示每个数据集的
运行状态。

Python:

```python
from workflow.batch import run_batch

result = run_batch(
    manager,
    "exp_001",
    ["data_001", "data_002"],      # 目标:显式 id,或 "group:<id>" / "all"
    ["fid", "spectrum", "peaks"],  # 步骤,按顺序
    backend,
    progress=lambda message: print(message),
)
```

## 与参数扫描的关系

两者解决的是不同问题,值得分清:

| | 批量 | 参数扫描(`nmrforge_api`) |
| --- | --- | --- |
| 变的是 | 数据集 | 处理参数 |
| 不变的是 | 方法 | 数据集与参考 |
| 回答的问题 | 「把这些都处理掉」 | 「结果对这些参数有多敏感?」 |
| 产出 | 逐数据集的谱与峰表 | 逐组合的谱、峰位与不确定度 |
| 维度 | 仅 2D | 2D 与 3D |

如果你要的是「同一个数据集上的参数网格」,请用 `nmrforge_api`;见
[external-api/README.md](external-api/README.md)。

## 边界

- 仅 2D。非 2D 成员跳过并报告;
- 批量不做「智能」的逐数据集参数选择:它套用组配置,这样输出之间的差异反映的是数据集之间的差异,
  而不是参数集之间的差异;
- 批量产出按数据集记录,不是一条批级别的 run 记录,所以半路中断的批仍然可解释。
