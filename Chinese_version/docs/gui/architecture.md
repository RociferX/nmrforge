# GUI 架构

桌面应用由 `gui/main_window.py` 组装。`MainWindow` 持有当前的 `ProjectManager`、
`ProcessingController`、项目树、流水线/中心面板、日志面板和谱图面板。切换项目时会更新
项目管理器所绑定的项目；项目 JSON 与数据条目通过 `core.project` 服务读写。正常应用入口
会在启动预热后构建谱图面板，使窗口可以先显示，再加载较重的绘图模块。

## 控制与处理

界面控件通过有类型的 Qt 信号发出用户操作，例如导入、运行处理步骤、编辑人工脚本、打开
谱图和停止任务。`MainWindow` 与 `PipelinePanel` 将这些请求连接到 `ProcessingController` 和
项目服务。控制器把 GUI 操作转接到 `workflow/` 函数，包括导入、生成 FID、生成谱图、选峰、
人工处理和数据组批处理。它还解析处理参数，并通过项目管理器登记步骤成功状态及脚本快照。

耗时的导入和处理在守护型 `threading.Thread` 工作线程中执行。进度、完成和失败通过 Qt
信号返回，槽函数在 GUI 主线程更新控件；工作线程不直接持有界面。控制器使用线程局部存储，
在各工作线程中按需创建 backend，因此并发任务不会共享 `NMRPipeBackend` 可变的工作目录。
流水线按 `(实验, 数据, 步骤)` 跟踪运行目标，并通过开始/完成信号更新对应数据行。停止操作
调用 backend 运行时的取消路径；`CshRuntime` 登记子进程，以便停止正在运行的命令进程树。

日志通过 Qt 信号送入可见的 `LogPanel`，可以按全局、数据条目或数据组划分作用域；任务输出
也会写入对应的运行记录。GUI 按数据和步骤保存非模态脚本编辑器的引用，直到对话框关闭；
同一数据步骤不会同时打开多个编辑器。

## 谱图加载与显示

`gui/spectrum_panel.py` 扫描所选数据条目的 spectra 目录，并打开 `.ft1`、`.ft2` 或 `.ft3`。
较小的 2D 文件可以同步读取；较大的 2D 文件和 3D 文件由后台线程加载。单调递增的加载令牌
标识最新选择；当令牌或路径不再匹配当前选择时，后台返回的结果和错误会被丢弃。处理成功后，
界面通过信号按已冻结的实验/数据目标重新加载谱图。

对于 3D `.ft3`，`Spectrum3D.load_from_ft3(..., lazy=True)` 会先读取文件头和轴信息。流式格式
通过 `nmrglue` 低内存接口按需读取平面；不支持的布局会回退到完整加载。首个平面和噪声估计
在工作线程中准备。GUI 将得到的 `Spectrum3D` 绑定到 `Spectrum3DPanel`，把选定的 2D 平面
交给 `SpectrumViewer` 显示，再于后台继续读取其他平面。平面数据保存在带锁且有容量上限的
`Spectrum3D` 缓存中；更换谱图或固定轴时，取消令牌会停止过期的平面流。面板持有当前 3D
对象，直到清除或替换；查看器持有用于绘制的当前 2D 切片对象。

平面选择器固定一个逻辑轴（F1、F2 或 F3），其余两个轴组成显示的 2D 切片。滑块选择固定轴
上的点，ppm 输入框将化学位移映射到最近点。面板发出 `slice_changed` 后，主窗口通知查看器
替换当前切片。如果查看器仅显示一张 3D 切片，`SpectrumViewer.update_spectrum_data()` 会
更新现有图像层，避免完全清空并重建视图。2D/3D 轴信息来自 NMRPipe 文件头：数据轴通过
`FDDIMORDER` 映射到 FDF 参数块，每个轴对象携带逻辑轴标签和 ppm 坐标。切片还会记录原始
维度索引，使峰坐标仍能对应到原 3D 轴。

独立查看器入口为 `viewer/app.py`，使用同一组谱图对象、面板和查看器控件。面向使用者的行为
见 [GUI 指南](../gui.md)；整体组件与数据流程见[架构](../architecture.md)。
