# 09 · 边界与扩展路径(v1.1.1)

## 9.1 支持矩阵

| 项目 | v1.1.1 | 说明 |
| --- | --- | --- |
| uniform 1D/2D/3D 数据 | ✅ 处理与完整逻辑轴峰表 | 走 NMRPipe `process()`；统一 38 列 CSV 含 F1/F2/F3 ppm、核名与等效 FWHM |
| NUS **2D** 数据 | ✅ 组合执行 | 走 `reconstruct_nus()`(SMILE),候选谱隔离输出;可扫 SMILE 参数 |
| NUS 3D 数据 | ⚠️ 只能建参考谱 | 组合执行会抛 `SweepError`(见 9.2) |
| 参考工作流(每条件一份) | ✅ | 各条件独立生成参考谱、峰身份表与参考峰表；外部峰表只应用于主条件 |
| workflow_id 批量执行 | ✅ | `W0001…`；各条件使用自己的参考基底，同一请求参数不代表峰对应 |
| 峰定位:三点抛物线 | ✅ | 唯一方法(2026-09-26 起二维高斯拟合算法已删除) |
| 多条件(A/B) | ✅ | 每条件独立选参考峰；外部峰表不传播，峰 ID 只在所属峰表内有效 |
| **实际满采样但标注 NUS** | 有条件按 uniform 处理 | 合法日程满覆盖且为标准顺序才直接常规 FT；全覆盖乱序仍需按表归位。NUS 声明下缺表/坐标未知拒绝导入，非零 `ser` 不足以证明 uniform |
| 峰重叠/去卷积 | ❌ | 只做窗口内极值 + 三点抛物线亚像素 |
| Lorentzian / Voigt / 多峰分解 | ❌ | 路线图项 |
| 并行/集群调度 | ❌ | 串行 + 断点续跑;按参数轴分片(见 8.4) |
| 参数轴合法性校验 | 部分 | 锁定键报错、确定性/未知键提示;键名有效性以 notes 提示为主 |
| 统计推断与科学结论 | ❌ **(不属本软件)** | 由使用者自己的分析从统一峰表计算 |

## 9.2 NUS 的支持范围

> **覆盖率与采集顺序分别判断**：合法日程满覆盖且为标准栅格顺序，可按 uniform
> 常规 FT 并留档 `sampling="uniform"` / `sampling_schedule="full_sampling"`。
> 全覆盖但乱序仍按日程展开归位；`NusAMOUNT=100`、文件填满网格或无零迹都不能替代
> 采样坐标证据。传统采集网格后的全零 padding 不当缺采点。明确 NUS 缺表且位置无法还原
> 时导入拒绝，不能强制 FT 或把失败数据送入 SMILE。

**已支持:2D NUS**。参考与 workflow 都走 `reconstruct_nus()`,差别只是工作流
批量执行会为每个组合隔离候选输出:

- 相位锁定:`phases`(间接维)+ 扁平 `direct_phase`(直接维);
- 候选输出 `study/workflows/<id>/<条件>/spectrum.ft2`(后端 `out_file`/
  `script_name` 语义),不覆盖工作目录里的终谱;
- 可扫参数:`nsigma`(别名 `nSigma`)、`thresh`、`nthread`、`smile_scaling` 等;
  自动分档时实际值写进 `parameters_resolved.smile`。

**仍未支持:3D NUS** 的组合执行(切片流按平面目录分桶 + 独立 finalize 命名)。

## 9.3 长批量怎么切分

- 组合数上限默认 256(`max_runs`);超过请拆成多个研究根或分批;
- 同一研究根内可反复重跑,已成功的 workflow × 条件会跳过(断点续跑);
- 当前续跑指纹 schema 为 `nmrforge_api.resume.v4`;此前 schema 的未匹配条目不会被当作
  可复用结果;
- 多机并行:按**参数轴**拆分(各机器不同子网格、各自研究根),分析侧合并长表;
- 每次改参数表前建议记录 `grid_sha256`(plan/manifest 里都有),便于核对是同一
  批设计。

## 9.4 roadmap

| 优先级 | 项 | 交付形态 |
| --- | --- | --- |
| 高 | 3D NUS 组合执行 | 切片流按 `workflow_id` 分目录 + finalize 输出隔离 |
| 中 | 峰拟合扩展到 Lorentzian/Voigt/多峰分解 | 目前只有三点抛物线亚像素定位(二维高斯拟合已于 2026-09-26 删除) |
| 中 | 参数键 schema 校验 | 报错而不是仅提示未知键 |
| 中 | 进度文件 | 每组合更新 `records/progress.json`,便于外部监控 |
| 中 | 3D 平面显式指定 | 峰表带固定维取值时按平面测量 |

用户新需求请附 `records/manifest.json` 与 `status` 输出,便于复现与定位。


## 9.5 验证与证据

常规pytest通过模拟引擎边界检查处理编排和记录，不执行NMRPipe或SMILE。
真实引擎验证另行记录输入、软件修订、引擎版本、参数及最终谱图/QC。

[四路径真实数据证据](../evidence/real-data-comparison.md)比较2D/3D uniform/NUS及注明来源的参考。
人工2D案例是uniform原始数据的受控下采样（请求75%，保留68/90）；3D NUS为实采25%。
这些案例的主要信号对应良好。候选覆盖率衡量检测与匹配，不是已指认真峰回收率，也不保证所有实验。

引用结果时记录软件/API版本、兼容声明与处理参数。生物学解释和实验专用科学验收由下游分析负责。

## 9.6 与主程序的关系：复用处理链，不免除入口验证

- API 复用主程序的 NMRPipe/SMILE 处理链、谱轴映射和选峰组件，不另造处理引擎。
- 参数合并、参考冻结、独立选峰、结果转表和断点复用仍有 API 入口逻辑，须独立验证。
  共用组件不能证明入口参数生效、所有轴坐标完整或导出的 QC 正确。
- `compat` 记录版本化行为与默认值，不是科学有效性认证。主程序的历史实测证据只支持
  当时实际测试的输入与路径，不能自动外推到所有 API 类型与参数组合。
- 主程序的当前真实数据证据见[真实数据实测证据](../evidence/real-data-comparison.md)。
  二维峰位对照不能验证三维碳轴；投影对照也不能覆盖完整三维峰重叠与伪影。
  维护者历史自述中无法复算的数据不作为本页证据。

## 9.7 如何解读运行记录

结合运行状态、警告、实际参数和最终谱图判断结果。兼容声明标识软件行为；
QC接受不等于确定峰身份或实验专用科学结论。

## 9.8 API 契约更新(2026-10-02)

本轮已修复并更新契约的项目如下；这几项不再属于当前未修问题:

- 每个条件独立生成参考峰表;外部峰表只作用主条件。`reference_peak_id` 是本地身份,不表示跨谱对应。
- 统一峰表为 38 列,含 F1/F2/F3 坐标、核名和等效 FWHM;重复核素时 H/N 兼容别名留空,
  判重使用完整逻辑轴坐标。
- targeted localization 仅对目标峰做三点抛物线精修;非目标峰停在检出整数格点,
  `localization_method="none"`,定位 QC 为 NaN(未计算)。
- `params.sweep_width_hz` 提供按逻辑轴覆盖谱宽的正有限 Hz 值,审计记录原值、实际值、来源与
  `consistency_ratio`;组合运行不能更改已转换数据的谱宽。
- `params_by_condition` 和 CLI `--condition-params` 提供逐条件参考覆盖。显式布尔 FT `neg`
  参数可作为组合候选(`ft_neg`/逐轴值及 `flip_*` 别名);相位与 `sampling.ft_alt` 仍锁定,
  全局 `ft_neg` 优先。
- CLI 在任何写入前拒绝不同的 `--study` 与 `--reference` 根;跨根运行不支持。相同根下组合
  会正常写入 workflow 与 records,不能视为只读参考。
- 转换记录保留数字滤波原始参数、脚本哈希与 bruk2pipe 参数,并记录阶段耗时和 FT
  `processing_audit` 的 requested/resolved/actual-command 证据。证据不足时数字滤波校正方法为
  `unknown`,不会由元数据推断已执行的处理。

低阈值性能优化不在本轮范围。由旧版共享身份或轴坐标不完整记录建立的参考,需显式重建后再按
当前独立峰表和完整轴字段使用。

API 正常职责只有处理与交接：参考谱/参考峰表、新谱/新峰表及其参数、脚本、QC 和来源。
跨谱对应、缺失机制和统计由下游负责。历史 uncertainty 辅助函数不参与两步处理，
不能未经下游匹配直接分析独立谱编号，也不构成 CSP 显著性判据。

## 9.9 FID 复用边界

参考阶段负责导入（若需导入）、转换及多段合并，并冻结可供组合复用的 FID、转换证据和
采样表。组合阶段只处理这些现有参考产物，然后独立选峰；覆盖单文件 FID、3D uniform
切片目录及多段合并 FID。组合不得自动重转或重合并，也不得清理源数据、修改参考 FID
或改写采样表。

若参考 FID 缺失或损坏、源输入/转换证据与参考不一致，或本次请求所需参数会触发转换或
合并，组合应直接报错并要求用户以 `force=True`（CLI `reference --force`）重新建立参考。
`force` 用于参考阶段重建，不会让组合模式现场补做转换。显式段频移等转换期参数也必须在
参考重建时确定。GUI 的默认转换与复用逻辑不由此 API 契约改变。

单文件、3D uniform 切片及多段合并的严格复用已通过 Linux 工程回归；旧参考缺少冻结
FID 留档时需要显式重建一次。指纹使用 ≤8 MiB 内容 SHA-256、大文件 size+mtime_ns，
不是内容级认证。此处不代表真实 NMRPipe/SMILE 引擎已验证，工程测试不能替代真机验收。
