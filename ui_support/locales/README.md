# Interface language packs

The model is described in `../i18n.py`: **the source language is English**, the code writes
`tr("English text")` - the public English tree and the private repository share one code
base, so the public tree carries no Chinese; Chinese is provided entry by entry by
`zh.json`.

- `source.json` - generated by `scripts/i18n_extract_ui.py --write`: the list of `tr()`
  strings (key -> where it is used), the Chinese coverage floor and the converted-file list;
  do not edit it by hand.
- `zh.json` - the Chinese catalogue (key = the English original). A missing entry falls back
  to the English original; nothing goes blank.
- `converted.json` - the files already converted (a ratchet: it only grows). Those files must
  not contain Chinese literals outside `tr()` any more.
- Language selection: explicit setting -> `NMRFORGE_LANG` / `NMRFORGE_LANGUAGE` -> **the
  preference stored in the user config** (`language:` in `nmrforge.local.yaml`, written by
  `Settings -> Software settings -> Interface language`) -> the system language (QLocale) ->
  `LANG` / `LC_ALL` -> `default.json` (the language this tree declares: private repository /
  Chinese edition = zh, public English tree = en). An AppImage pins it with `NMRFORGE_LANG`.
- `NMRFORGE_LANG` and `LANG` are not the same rank: the former is an explicit pin (above the
  setting), the latter is just the system locale (below it) - otherwise the `en_US.UTF-8` that
  Linux machines almost always have would defeat the setting forever.

Tool:

```bash
python scripts/i18n_extract_ui.py --report   # how many bare Chinese strings are left
python scripts/i18n_extract_ui.py --write    # refresh source.json / converted.json
python scripts/i18n_extract_ui.py --check    # guard (run --write first, then commit)
```

Literals that must not be translated (file headers, internal keys, comments inside style
sheets) are exempted explicitly with `# i18n: keep` on the same or the previous line.
